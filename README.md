# Lazarr

### Telegram-бот

Одобренные пользователи получают уведомления, когда для серии автоматически найдена раздача или требуется ручной выбор (в том числе после проверки файла). События собираются за 8 секунд в одну сводку на задачу и получателя; последующие события обновляют это же сообщение. Сводка содержит название сериала, номера серий и найденные раздачи. Очередь доставки и ID сводки сохраняются при перезапуске, ошибки Telegram повторяются с задержкой. Если сообщение удалено, бот отправляет новое.

Кнопка «Выбрать раздачу» открывает список серий, которым нужен выбор, затем варианты с пагинацией, размером и числом сидов. Выбранная раздача автоматически применяется также к другим подходящим сериям той же задачи, ожидающим выбора, в том числе из других сезонов. Перед загрузкой бот показывает охват, номера серий и предупреждения о несовпадении требований. Уже выбранные, загруженные серии и ранее отклонённые для этой раздачи варианты не затрагиваются; обработанные серии исчезают из списка. Старые кнопки, чужие уведомления и отозванный доступ не позволяют запустить загрузку. Если видеофайл нельзя определить автоматически, ручное сопоставление остаётся в WebUI.

В настройках откройте блок **Telegram** и вставьте токен от `@BotFather` — он проверяется
и сохраняется автоматически, после чего бот включается.
Используется long polling: публичный адрес и входящий порт не нужны. Один токен должен
использоваться только одним экземпляром Lazarr; существующий webhook нужно отключить.
Токен хранится зашифрованным и не возвращается через API настроек.

После `/start` в личном чате бот подтверждает отправку заявки. Администратор принимает
или отклоняет её в настройках; пользователь получает ответ. Повторная команда не создаёт
дубликат и не снимает блокировку. В попапе **Заблокированные пользователи** кнопка
**Разрешить доступ** исправляет ошибочный отказ и отправляет подтверждение пользователю.
Авторизованного пользователя можно заблокировать повторно. Заявки обновляются автоматически,
сохраняются после перезапуска и привязаны к конкретному боту. Ответы сохраняются до успешной
отправки, ошибки доставки видны рядом с пользователем. При смене бота его заявки учитываются
отдельно.

После одобрения доступна команда `/search` («Поиск»): название → результаты TMDB общей
картинкой по шесть обложек → сезон (для сериала) → языки озвучки и субтитров → задача.
Требования к качеству берутся из настроек Lazarr. Бот сообщает об автоматическом выборе
раздачи или предлагает до шести лучших сопоставленных вариантов, с указанием покрытия
эпизодов и количества сидов. Задачи общие с WebUI; действия выполняются от имени
одобрившего администратора и дополнительно отмечаются Telegram ID в журнале.
Предыдущий экран редактируется или удаляется; введённые команды и названия удаляются.
Telegram ограничивает удаление сообщений старше 48 часов. Диалог и очередь входящих
команд сохраняются после перезапуска. Уведомления о новых эпизодах пока не реализованы.

Лёгкий медиаменеджер на Python: поиск произведений, задачи с отдельными подтасками для эпизодов, объяснимое сопоставление раздач и встроенный libtorrent.

**ContentProvider ищет кандидатов по внешним признакам. Worker проверяет фактические файлы, связывает дорожки с видео и проверяет каждую подтаску.**

## Что реализовано

- Тёмный WebUI: поиск карточками, создание, редактирование и удаление задач, посерийный статус, загрузки, настройки.
- Несколько аккаунтов; сейчас все создаются администраторами. Проверки разрешений выделены в отдельный слой.
- Одна общая задача на медиа: несколько сезонов, выбор серий, общие требования к аудио, субтитрам и качеству.
- TMDB; контент-провайдеры Nyaa, Rutracker и Kinozal с авторизацией и сохранением cookies; CAPTCHA для Rutracker.
- Провайдеры как одиночные Python-файлы: каталог по HTTPS, проверка SHA-256/SDK, автообновление, локальный кэш.
- Ежедневный планировщик с временем начала поиска, календарём TMDB и обновлением эпизодов сезона.
- Worker с `MATCH / MISMATCH / UNKNOWN`, ручным выбором и ручной привязкой файлов.
- libtorrent: выбор файлов, порядок эпизодов, приоритет внешних дорожек, F/L pieces first, sequential download, resume data, ratio.
- Проверка скачанных файлов через ffprobe; готовые релизы автоматически не заменяются.

Произвольные пользовательские библиотеки, встроенный плеер и автоматическая распаковка архивов из раздач не входят в эту версию. Доступны три автоматические библиотеки: сериалы, кино и аниме.

## Запуск в Docker

Готовый образ опубликован как `drun555/lazarr:latest`:

```bash
docker pull drun555/lazarr:latest
```

```bash
mkdir -p downloads/movies downloads/series
docker compose up -d
```

Откройте **http://localhost:8000**. При первом открытии создайте аккаунт администратора в браузере. После этого вы автоматически войдёте в настройки. Онбоардинг закрывается после создания первого аккаунта; остальные аккаунты добавляются в настройках. CLI `lazarr create-admin admin` остаётся необязательной альтернативой.

В локальной среде `nix develop` заголовок вкладки помечается `[TEST] Lazarr`. Для другой тестовой среды задайте `LAZARR_TEST=1`; без этой переменной заголовок остаётся `Lazarr`.

Контейнер по умолчанию запускает Lazarr под UID/GID 1000. Entrypoint от root подготавливает владельца подключённых каталогов и затем понижает права; UID/GID можно переопределить переменными `PUID` и `PGID` (в Unraid по умолчанию 99/100). `/data` и `/plugins` используют постоянные именованные volumes; `/downloads` — bind mount. Пути в настройках указываются **внутри контейнера**: `/downloads/movies` и `/downloads/series`.

Переменные Compose: `TZ` (по умолчанию UTC), `LAZARR_DOWNLOADS` (по умолчанию `./downloads`), `LAZARR_SECURE_COOKIE=1` при работе через HTTPS reverse proxy. Порт UI — 8000, BitTorrent — 6881 TCP/UDP.

Dockerfile использует системный Python и соответствующий ему пакет `python3-libtorrent` из Debian. Виртуальное окружение видит системные bindings; плагины не устанавливают пакеты и не требуют пересборки образа.

## Unraid

Готовый шаблон находится в [`unraid/lazarr.xml`](unraid/lazarr.xml). Его можно добавить через Docker → Add Container → Template repositories, указав адрес репозитория, либо скопировать XML в `/boot/config/plugins/dockerMan/templates-user/`.

Шаблон создаёт постоянные каталоги для базы и плагинов, открывает WebUI на порту 8000 и BitTorrent на TCP/UDP 6881. Путь `/downloads` по умолчанию направлен в `/mnt/user/downloads/lazarr`; его можно изменить перед установкой. Для обхода Cloudflare разверните Trawl отдельно и укажите доступный из контейнера URL в `LAZARR_TRAWL_URL`.

## NixOS / Linux

В NixOS:

```bash
nix develop
python -m lazarr.cli serve
```

`flake.lock` фиксирует nixpkgs. В окружении есть Python, библиотеки приложения, libtorrent, ffmpeg/ffprobe, pytest и ruff.

На другом Linux с Python 3.12+ установите **системные** bindings libtorrent для выбранного Python и ffmpeg, затем:

```bash
python3 -m venv --system-site-packages .venv
. .venv/bin/activate
pip install -r requirements.lock
pip install --no-deps -e .
lazarr serve
```

По умолчанию локальный сервер слушает `127.0.0.1:8000`. Для локальной сети: `lazarr serve --host 0.0.0.0`. Один процесс обслуживает один каталог данных; второй экземпляр с тем же каталогом отклоняется.

Для замеров HTTP включите `lazarr serve --log performance` или `LAZARR_LOG=performance`.
В лог добавляются длительность каждого запроса, время до заголовков и request ID;
ответы содержат `Server-Timing` и `X-Request-ID`. Методика замеров и план оптимизации:
[docs/performance-plan.md](docs/performance-plan.md).

Кнопка **Tasks** в верхней навигации показывает очередь фоновых вычислений,
выполняющиеся задания и 30 недавних результатов.
Отдельная секция «Загрузки» показывает текущие загрузки, включая приостановленные и с ошибкой,
с прогрессом, скоростью и ETA; завершённые и раздающиеся торренты в неё не входят.
NextUp, Items, Latest, карточка Jellyfin и сборка карточки WebUI
работают в отдельном потоке каталога; thumbnails глав, trickplay, обработка
изображений, субтитров, вложений и ffprobe — в отдельном потоке медиа.
Одновременно работают два вычислителя (по одному в каждом потоке), до 64
заданий принимаются суммарно. При переполнении API возвращает 503 с Retry-After.
Одинаковые одновременные запросы генерации ресурса объединяются; отключение
клиента не прерывает общую работу. Результат NextUp не кэшируется, запрос ждёт
актуального расчёта, не блокируя event loop.

Ресурсы (например, trickplay) генерируются по запросу, без прогрева всего видео.
Отдельные фоновые циклы после старта и далее с паузой 60 секунд обновляют старые
метаданные и анализируют неизвестные языки субтитров. Сетевой этап метаданных
асинхронный и не занимает вычислительный поток. Языки, включая `und`, сохраняются
в probe в БД; результат привязан к пути, размеру, mtime, дорожке и версии алгоритма.
Чтение каталога не запускает языковой ffmpeg или обновление метаданных провайдера.
Интервал повторной попытки metadata enrichment — 5 минут, сохраняется в БД.
При отключённом background новые результаты автоматически не подготавливаются.

Очередь и история заданий хранятся в памяти, результаты анализа — в БД,
сгенерированные ресурсы — в файловом кэше. После аварийного рестарта анализ
продолжит периодический обход, генерацию ресурса повторно инициирует клиент.
При штатном завершении сервер дожидается принятых заданий до закрытия базы.
Полная персистентная очередь с управлением заданиями пока не реализована.

WebUI опрашивает прогресс раз в 3 секунды, карточку целиком — раз в 30 секунд
или при смене состояния загрузки; действия пользователя обновляют её сразу.
Опросы не накладываются, при ошибках интервал увеличивается до 30 секунд,
при скрытой вкладке и открытом Tasks периодическое обновление библиотеки приостановлено.

## Первоначальная настройка

1. В секции TMDB сохраните API key либо Read Access Token. При необходимости измените базовый URL API, сохранив суффикс `/3`.
2. Включите нужные источники: Nyaa, Rutracker, Kinozal. Для Rutracker сохраните учётные данные и нажмите «Войти»; при запросе введите CAPTCHA. Можно использовать `bb_session`. Для Kinozal задайте URL зеркала (по умолчанию `https://kinozal.me`), логин и пароль, затем нажмите «Войти». Вместо пароля можно сохранить cookies в формате `uid=…; pass=…`. При проверке Cloudflare потребуется Trawl.
3. Укажите папки загрузок, языки и разрешение по умолчанию, расписание и ratio. Языки выбираются через автокомплит: выбранные значения появляются плашками, крестик убирает язык. Поиск принимает названия и коды (`jap`, `rus`, `English`).
4. В поиске выберите произведение и один или несколько сезонов через «Добавить сезон». Для каждого сезона можно задать серии `1, 2, 5–8`; пустое поле означает весь сезон с добавлением новых эпизодов. Требования к качеству и языкам общие для задачи.

Контент-провайдеры изначально выключены. Без них задачи сохраняются, а интерфейс сообщает, почему поиск раздач не выполняется. Для живого TMDB нужен пользовательский ключ; для закрытых возможностей Rutracker — пользовательская авторизация.

## Семантика требований

- Языки в интерфейсе показаны названиями. Принимаются также коды и английские названия: `Русский / ru / rus / russian`, `Японский / ja / jap / jpn / japanese`. Все указанные языки аудио обязательны; пустой список снимает ограничение.
- Качество — только разрешение, в пределах минимума и максимума.
- Обязательная фраза — подстрока заголовка/описания без учёта регистра.
- Отсутствующие субтитры не блокируют скачивание. Их языки сохраняются отдельно в результате проверки файла.
- Провайдерские списки файлов — подсказки. Worker сопоставляет реальные пути из torrent metadata.
- При неоднозначной нумерации, неизвестном языке или противоречивых сведениях нужна ручная проверка. Абсолютная нумерация аниме автоматически не переводится в сезоны без явного соответствия.
- Нет распознавания языка по звуковому сигналу и проверки синхронизации чужих монтажей. Для внутренних дорожек используются теги контейнера; для внешних — также привязка и язык имени файла.

В «Раздачах» доступны объяснения критериев, выбор кандидата, отклонение и ручное сопоставление видео/дорожек. Ручное исключение относится к конкретной подтаске и ревизии торрента. При ручном выборе фактическое разрешение сохраняется в отчёте, но не блокирует файл, даже если выходит за заданные границы качества. Подтверждённое несоответствие аудио по-прежнему запрещает назначать версию текущей; для автоматического выбора ограничения качества сохраняются.

«Найти другие раздачи» запускает явный поиск вариантов для одной серии, в том числе завершённой или на паузе. Этот поиск не меняет выбранные файлы и ничего автоматически не скачивает: замена происходит только после выбора пользователем.

## Загрузки и расписание

«Готово к просмотру» означает, что доступны начало, конец, первые 32 MiB видео и найденные необходимые внешние дорожки, а ffprobe читает контейнер. Для просмотра нужен внешний плеер с доступом к файлам. Возможны остановки воспроизведения, если плеер догонит загрузку.

«Готово» означает полную загрузку и проверку файлов эпизода; торрент при этом может продолжать сидирование. Ratio хранится на физический торрент, сохраняется между перезапусками. `0` останавливает раздачу после скачивания, пустое значение означает отсутствие лимита. Значение фиксируется при создании загрузки.

Поиск запускается ежедневно во «Время начала поиска» (по умолчанию 00:00) и выполняет полный проход без времени окончания. Завершённый проход сохраняется в БД, поэтому перезапуск не запускает его повторно; незавершённый продолжается. Если приложение было выключено в момент старта, проход начинается при запуске. Часовой пояс берётся из `TZ` (например, `TZ=Europe/Saratov docker compose up -d`), без `TZ` — из `/etc/localtime` хоста. Будущая дата выхода блокирует поиск; неизвестная — разрешает. Дата без времени считается наступившей после окончания соответствующего дня. Загрузки и сидирование работают независимо от расписания.

Автоматическая замена скачанных релизов отключена. Для каждой серии можно изменить раздачу или сопоставление видео и внешних дорожек на любом этапе, включая готовые серии и задачи на паузе. Новый выбор сразу заменяет прежний: старые файлы удаляются, если не нужны другим сериям, и больше не публикуются в библиотеке. Для общего торрента удаляются только ненужные файлы; после замены последнего потребителя удаляется вся старая загрузка. Очистка сохраняется в БД и повторяется при ошибке; торрент с незавершённой очисткой не возобновляется до её завершения. История файлов серии не сохраняется. При запуске прежние версии существующих серий очищаются с сохранением актуального выбора.

## Плагины и репозиторий

Начальные TMDB/Nyaa/Rutracker/Kinozal входят в образ как файлы. URL публичного каталога проекта пока не задан: укажите собственный HTTPS-каталог в настройках. Для публикации этих же адаптеров:

```bash
python scripts/build_catalog.py --base-url https://your-host.example/lazarr/providers
```

Разместите `catalog.json` и `.py` из `src/lazarr/bundled` по этому адресу; укажите полный URL `catalog.json`. Каталог может находиться в Git-репозитории, если URL возвращает сырые файлы. Поля URL в начальном каталоге — примеры; bootstrap читает локальные файлы и не обращается к ним.

Плагины — доверенный Python-код, исполняемый в процессе Lazarr. Контрольная сумма проверяет целостность относительно доверенного каталога; это не песочница. Секреты и cookies шифруются ключом `/data/secret.key`; резервная копия должна сохранять ключ вместе с БД. Сами torrent metadata могут содержать приватные tracker passkeys и хранятся с ограниченными правами.

Подробнее: [архитектура](docs/architecture.md), [SDK провайдеров](docs/plugins.md), [проверки](docs/testing.md).

## Разработка и тесты

```bash
nix develop
pytest -q
ruff check src tests scripts
ruff format --check src tests scripts
npm ci
npm run test:ui
node --check src/lazarr/static/app.js
```

Тесты swarm используют только loopback и синтетические медиа, без публичных трекеров. Без libtorrent или ffmpeg соответствующие тесты пропускаются с объяснением; полный приёмочный прогон выполняйте в Nix-окружении.

Миграции применяются при запуске. Также доступно `lazarr migrate`. OpenAPI: `/docs`, схема: `/openapi.json`; все прикладные API требуют сессии, изменения — заголовка `X-CSRF-Token`.

## Cloudflare / Trawl

Для защищённых страниц Rutracker и Kinozal предусмотрен отдельный необязательный сервис:

```bash
docker compose --profile cloudflare up -d --build
```

Lazarr обращается к `http://trawl:8191` внутри сети Compose; порт Trawl наружу не публикуется. В настройках Rutracker можно указать другой адрес. Для локального запуска задайте `LAZARR_TRAWL_URL=http://127.0.0.1:8191` либо поле провайдера. Trawl нужен только при обнаружении проверки Cloudflare. Cookies и User-Agent браузера сохраняются в зашифрованной сессии провайдера; затем Lazarr повторяет исходный запрос. HTML можно получить через браузер, torrent-файлы и CAPTCHA-изображения скачиваются как двоичные данные. Неуспешная проверка приводит к понятной ошибке и паузе в 5 минут.

Trawl использует совместимый API `/v1` и браузер Camoufox. CAPTCHA самого трекера остаётся отдельным шагом входа; результат зависит от текущей защиты сайта. [Документация Trawl](https://github.com/germondai/trawl).

## Обложки и нумерация аниме

Обложки TMDB загружаются через авторизованный endpoint Lazarr и сохраняются в `/data/posters`. Браузеру не нужен прямой доступ к `image.tmdb.org`. В настройках TMDB есть отдельное поле «URL изображений» с размером, например `https://image.tmdb.org/t/p/w342`. Переопределение API URL не меняет адрес изображений.

TMDB иногда объединяет несколько телевизионных сезонов в один непрерывный список. Если TMDB предоставляет однозначную группу `Seasons`, форма предлагает обычные сезоны отдельно от исходной нумерации TMDB. Задача сохраняет выбранную схему, а `Episode` остаётся каноническим: разные варианты нумерации используют одни эпизоды. Обновление целого сезона добавляет только эпизоды выбранного сезона.

Проверенный пример: **Re:Zero, TV-2, часть 2** — выбрать «Сезон 2 · 25 серий», серии `14–25`. В TMDB это сезон 1, серии `39–50`. Worker использует явную связь из группы TMDB, а не вычисляет смещение по размеру пакета. Файлы с неоднозначной нумерацией или неподтверждённым языком требуют ручного выбора.

Новые версии встроенных плагинов активируются автоматически. При запуске и каждый час Lazarr проверяет настроенный HTTPS-каталог; при недоступности сети использует локальные копии. Выполняющиеся вызовы заканчиваются на прежней версии. Иконка **Revert** сбрасывает поля конфигурации провайдера к значениям по умолчанию; изменения, включая очистку секретов, применяются кнопкой «Сохранить».

Старые настройки `flaresolverr_url` и `LAZARR_FLARESOLVERR_URL` продолжают работать до переноса адреса в новое поле Trawl.

## Удаление задач

Кнопка «Удалить» открывает диалог с отдельным переключателем удаления медиа и загрузок. По умолчанию файлы и их проверенная привязка к библиотеке сохраняются, загрузка без потребителей останавливается: сезоны и серии продолжают отображаться и воспроизводиться через Jellyfin API. При включённом переключателе удаляются все версии, принадлежащие только этой задаче; общие загрузки сохраняются, пока нужны другим задачам. Канонические Media/Season/Episode остаются независимыми от задач. Очистка файлов фиксируется в БД и повторяется при ошибке или перезапуске; пути с подменой через symlink отклоняются.

## Запуск очереди и наблюдение за поиском

При создании задачи запрос на поиск сохраняется в той же транзакции. Worker начинает его сразу, независимо от ежедневного расписания; интерфейс открывает «Библиотеки». Если Worker занят, новая задача ожидает своей очереди без задержки ответа API создания. Паузы, даты выхода, ограничения провайдеров и общие загрузки сохраняют своё действие.

Кнопка «Запустить все задачи» на общем экране библиотек запускает поиск всех подходящих незавершённых задач, включая задачи, для которых запланирована следующая попытка. Повторные нажатия во время ожидания объединяются. Запросы переживают перезапуск. Если провайдеры выключены, очередь ждёт их включения.

В карточке медиа над сезонами расположен аккордион «Задача»: выбранные сезоны и серии, требования, запуск поиска этой задачи, пауза, изменение и удаление. Ход поиска и журнал относятся только к этому медиа. Кнопка «Скачать» у сезона добавляет его в существующую задачу с сохранением требований; если задачи ещё нет, создаёт её. На экране поиска кнопка «Открыть» ведёт к управлению задачей в библиотеке.

Во вкладке «Библиотеки» видны текущий провайдер и запрос, страница результатов, проверка описания, получение торрент-структуры, сопоставление файлов и передача в загрузку. У каждой серии показываются её состояние, прогресс, скорость, ETA и выбранная раздача; там же можно сменить источник или приостановить физическую загрузку. На тайле произведения во время скачивания появляется общий прогрессбар. Раздел «Ход поиска» содержит последние 40 действий текущего прохода. История действий хранится в памяти; сама очередь — в SQLite.

Для тестов интерфейса используется Node.js с jsdom (`npm ci && npm run test:ui` внутри `nix develop`). Node.js не нужен при запуске Lazarr или в Docker.

В отчёте поиска отдельно показан каждый контент-провайдер: выключен, ожидает, выполняет поиск, проверяет кандидатов, завершил или вернул ошибку. Временная пауза показывает исходную ошибку и время разрешённого повтора. Если ни один поисковый запрос не был успешным, проход обозначается «Поиск не выполнен». Ошибка одного включённого провайдера не прерывает поиск по остальным.

В настройках контент-провайдеров стрелки ↑/↓ задают порядок включённых провайдеров: верхний опрашивается первым. Порядок сохраняется сразу и переживает перезапуск; уже начатая группа запросов заканчивается в прежнем порядке. Ошибка или временная пауза одного провайдера не мешает опросить следующий. Порядок опроса не отменяет сравнение качества найденных кандидатов.

Между исходящими HTTP-запросами к одному контент-провайдеру выдерживается минимум 2 секунды, в том числе между отдельными вызовами плагина. Повторные ручные запуски в пределах 2 секунд объединяются; первая команда и создание новой задачи не задерживаются. После HTTP 429 и ошибок доступности пауза растёт от 1 минуты до 1 часа. `Retry-After` (секунды или HTTP-дата) задаёт минимальный срок ожидания и может увеличить его. Пауза и число последовательных ошибок сохраняются в БД; ручная проверка провайдера не обходит паузу. HTTP 504 означает ошибку доступности, а не подтверждённый rate limit ресурса.

Поиск сохраняет основное написание названия, затем при незакрытых требованиях пробует перечисленные в метаданных варианты его пунктуации и пробелов. Случайные переводы из списка aliases не подставляются: например, для Re:Zero используются `Re:Zero`, `Re Zero`, `ReZero`. Каждый вариант ограничен тремя страницами; в журнале показываются фактический текст и смещение запроса. Rutracker передаёт категорию из выдачи для предварительного отбора. Явно неподходящие типы материалов, сезоны и разрешения отсеиваются до чтения темы, обязательная фраза и полные заявления об аудио — до получения torrent. Неизвестные сведения сохраняют кандидата для дальнейшей проверки.

Worker проверяет перспективные кандидаты первыми и прекращает поиск после покрытия запрошенных эпизодов подходящими раздачами. Скачанные и проверенные эпизоды исключаются из повторного поиска, в том числе ручного. Когда все запрошенные эпизоды готовы, задача помечается завершённой. Новые эпизоды отслеживаемого сезона или добавление сезона снова делают её незавершённой. Изменение требований относится только к ещё не скачанным эпизодам; готовые файлы автоматически не заменяются. Год выпуска сезона сопоставляется с датами эпизодов и явной нумерацией сезона, а не только с годом начала сериала. Фактическая проверка файлов остаётся обязательной.

При паузе провайдера обработка его оставшихся кандидатов и страниц прекращается. В SQLite сохраняется отложенный запрос задач для этого провайдера; остальные провайдеры продолжают работу. После паузы поиск повторяется без кэша выдачи, описаний или результатов проверки. Счётчики различают найденных, отсеянных, проверенных, отложенных кандидатов и ошибки проверки. Отложенное количество относится к уже полученной странице, не к неизвестному размеру всей выдачи.

Очередь эпизодов внутри торрента управляется явно: скачиваются первая незавершённая серия и связанные с ней дорожки; файлы следующих серий временно имеют приоритет 0. После завершения текущей серии очередь продвигается независимо от физического порядка файлов в раздаче. Уже полученные данные сохраняются. Начало и конец текущего видео получают piece deadlines, остальная часть скачивается последовательно. Небольшое количество данных соседнего файла может попасть в общий пограничный piece.

## Библиотеки

Вкладка «Библиотеки» содержит три автоматических раздела: «Сериалы», «Кино», «Аниме». Произведение показывается один раз независимо от числа задач и пользователей. Аниме определяется по жанру Animation (TMDB 16) и стране JP либо исходному языку ja; остальные произведения распределяются по типу movie/tv. Японское название само по себе не означает аниме. Недостающие признаки старых записей дополняются из метаданных при открытии библиотек; при недоступности провайдера локальные записи остаются доступны, с отметкой об уточнении классификации. Это логические разделы, они не перемещают файлы на диске.

Карточка произведения показывает описание, обложку, жанры, известные эпизоды с альтернативной нумерацией, календарь дат выхода, последний поиск, выбранный файл, качество, встроенные и внешние дорожки и раздачу. Серии сгруппированы по сезонам в accordion-блоки. Для отсутствующего или недоступного изображения выводится спокойная тёмная заглушка с номером серии вместо сломанной картинки. Непроверенные сведения обозначаются отдельно. Кнопка «Изменить файлы» открывает текущее сопоставление видео и внешних дорожек; «Выбрать раздачу» позволяет сменить источник. Эпизоды без задач или выбранных файлов тоже видны. Последний поиск сохраняется с миграции 0005 при реальной попытке обращения к контент-провайдеру; старые даты не восстанавливаются предположительно.

## Jellyfin-совместимый API

К адресу Lazarr можно подключить Jellyfin-клиент как к серверу. Вход выполняется с учётной записью Lazarr. API предоставляет три библиотеки, произведения, сезоны, загруженные серии, обложки, сведения о воспроизведении, внешние субтитры и прямую HTTP-выдачу файлов с Range-запросами. Позиция, завершённость, число просмотров и время последнего просмотра сохраняются отдельно для каждого аккаунта; незавершённые элементы возвращаются в «Продолжить просмотр».

Пользовательское состояние сохраняется в SQLite: избранное, оценки «нравится/не нравится», числовой Rating, настройки отображения отдельно для пользователя, клиента и представления. `/Items` поддерживает фильтры избранного, оценок, просмотренного и возобновляемого видео, а также сортировку по имени, дате и числу просмотров. `/UserItems/{id}/UserData` обновляет только переданные поля; идентификатор пользователя в запросе должен соответствовать токену.

Видеоплейлисты доступны через `/Playlists` и `/Items?IncludeItemTypes=Playlist`. Владелец задаёт публичное чтение или доступ конкретным аккаунтам с правом редактирования состава и названия. Управлять доступом и удалять плейлист может только владелец. Повторы видео имеют независимые стабильные PlaylistItemId, порядок и права сохраняются после перезапуска. `DELETE /Items/{id}` разрешён только для плейлистов; медиа при этом не удаляются.

Сеансы просмотра сохраняют файл, часть, позицию и результат воспроизведения. PlayCount увеличивается один раз при начале сеанса (или первом отчёте, если клиент пропустил начало), повторные Progress/Stopped не дублируют просмотр. При повторном просмотре Played сохраняется, а новая позиция появляется в Resume. Позиции до 5% не попадают в Resume, достижение 90% завершает просмотр. Ошибка проигрывателя не завершает видео. Клиентам рекомендуется передавать PlaySessionId; без него последовательные просмотры одного аккаунта различаются по Playing/Stopped, а одновременные просмотры с общим токеном надёжно разделить нельзя.

Resume поддерживает библиотеку/родителя, типы, поиск, пагинацию и исключение активных сеансов. Next Up выбирает следующую доступную серию после просмотренных, учитывает enableResumable, enableRewatching, seriesId, parentId и nextUpDateCutoff. Specials без обычного номера сезона не включаются. OrderedViews, MyMediaExcludes и HidePlayedInLatest применяются к соответствующим представлениям.

Для сохранённых версий доступны отдельные позиции и точный MediaSourceId; завершение версии очищает Resume остальных версий той же части. Идентификатор части сохраняется в истории, и разные части не завершаются друг за друга. Автоматическое обнаружение и создание многочастных фильмов не добавлено: текущий загрузчик публикует один файл фильма или эпизода. Старые позиции просмотра сохраняются при миграции; история сеансов до миграции не восстанавливается предположительно.

Каталог поддерживает расширенные запросы, поиск, справочники, read-only коллекции, Similar/Recommendations и проекцию DTO. Добавлены хронологический Latest, Upcoming, главы и их изображения, trickplay, сегменты по именованным главам, локальные трейлеры и дополнительные видео. Текстовые субтитры извлекаются и конвертируются, в том числе в WebVTT HLS; доступны вложенные и fallback-шрифты.

Приоритет дорожек берётся из отдельных настроек Jellyfin и пользовательских предпочтений. Основной поток передаётся без перекодирования; подтверждённое внешнее аудио можно смешивать с видео в Matroska через stream copy. Контейнер и кодеки должны поддерживаться клиентом. Прямое воспроизведение доступно также для buffer-ready эпизодов; произвольное извлечение preview-ресурсов рассчитано на полностью скачанные файлы. Маршруты редактирования метаданных/библиотек и SyncPlay не добавлены.

Точный список маршрутов, параметров, поведения кэша и оставшихся ограничений: [Jellyfin video API](docs/jellyfin-video-api.md).
