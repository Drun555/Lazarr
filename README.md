# Lazarr

Лёгкий медиаменеджер на Python: поиск произведений, задачи с отдельными подтасками для эпизодов, объяснимое сопоставление раздач и встроенный libtorrent.

**ContentProvider ищет кандидатов по внешним признакам. Worker проверяет фактические файлы, связывает дорожки с видео и проверяет каждую подтаску.**

## Что реализовано

- Тёмный WebUI: поиск карточками, создание, редактирование и удаление задач, посерийный статус, загрузки, настройки.
- Несколько аккаунтов; сейчас все создаются администраторами. Проверки разрешений выделены в отдельный слой.
- Общая сущность `Media` для задач разных пользователей и сезонов. Собственные требования каждой задачи.
- TMDB; контент-провайдеры Nyaa и Rutracker с авторизацией/cookies/CAPTCHA.
- Провайдеры как одиночные Python-файлы: каталог по HTTPS, проверка SHA-256/SDK, автообновление, локальный кэш.
- Podnapisi без регистрации и OpenSubtitles с API key как файловые провайдеры: ручная загрузка недостающих субтитров для готовых файлов.
- Ежедневный планировщик с временем начала поиска, календарём TMDB и обновлением эпизодов сезона.
- Worker с `MATCH / MISMATCH / UNKNOWN`, ручным выбором и ручной привязкой файлов.
- libtorrent: выбор файлов, порядок эпизодов, приоритет внешних дорожек, F/L pieces first, sequential download, resume data, ratio.
- Проверка ffprobe и улучшение разрешения без удаления предыдущих файлов.

Произвольные пользовательские библиотеки, встроенный плеер и автоматическая распаковка архивов из раздач не входят в эту версию. Доступны три автоматические библиотеки: сериалы, кино и аниме.

## Запуск в Docker

Готовый образ опубликован как `drun555/lazarr:latest`:

```bash
docker pull drun555/lazarr:latest
```

```bash
mkdir -p downloads/movies downloads/series
docker compose up -d
```

Откройте **http://localhost:8000**. При первом открытии создайте аккаунт администратора в браузере. После этого вы автоматически войдёте в настройки. Онбоардинг закрывается после создания первого аккаунта; остальные аккаунты добавляются в настройках. CLI `lazarr create-admin admin` остаётся необязательной альтернативой.

Контейнер работает под UID 1000. Каталог `downloads` на хосте должен быть доступен этому UID для записи. `/data` и `/plugins` используют постоянные именованные volumes; `/downloads` — bind mount. Пути в настройках указываются **внутри контейнера**: `/downloads/movies` и `/downloads/series`.

Переменные Compose: `TZ` (по умолчанию UTC), `LAZARR_DOWNLOADS` (по умолчанию `./downloads`), `LAZARR_SECURE_COOKIE=1` при работе через HTTPS reverse proxy. Порт UI — 8000, BitTorrent — 6881 TCP/UDP.

Dockerfile использует системный Python и соответствующий ему пакет `python3-libtorrent` из Debian. Виртуальное окружение видит системные bindings; плагины не устанавливают пакеты и не требуют пересборки образа.

## Unraid

Готовый шаблон находится в [`unraid/lazarr.xml`](unraid/lazarr.xml). Его можно добавить через Docker → Add Container → Template repositories, указав адрес репозитория, либо скопировать XML в `/boot/config/plugins/dockerMan/templates-user/`.

Шаблон создаёт постоянные каталоги для базы и плагинов, открывает WebUI на порту 8000 и BitTorrent на TCP/UDP 6881. Путь `/downloads` по умолчанию направлен в `/mnt/user/downloads/lazarr`; его можно изменить перед установкой. Для обхода Cloudflare разверните FlareSolverr отдельно и укажите доступный из контейнера URL в `LAZARR_FLARESOLVERR_URL`.

## NixOS / Linux

В NixOS:

```bash
nix develop
python -m lazarr.cli serve
```

`flake.lock` фиксирует nixpkgs. В окружении есть Python, библиотеки приложения, libtorrent, ffmpeg/ffprobe, pytest и ruff.

На другом Linux с Python 3.12+ установите **системные** bindings libtorrent для выбранного Python и ffmpeg, затем:

```bash
python3 -m venv --system-site-packages .venv
. .venv/bin/activate
pip install -r requirements.lock
pip install --no-deps -e .
lazarr serve
```

По умолчанию локальный сервер слушает `127.0.0.1:8000`. Для локальной сети: `lazarr serve --host 0.0.0.0`. Один процесс обслуживает один каталог данных; второй экземпляр с тем же каталогом отклоняется.

## Первоначальная настройка

1. В секции TMDB сохраните API key либо Read Access Token. При необходимости измените базовый URL API, сохранив суффикс `/3`.
2. Включите Nyaa и/или Rutracker. Для Rutracker сохраните учётные данные и нажмите «Войти»; при запросе введите CAPTCHA. Можно использовать `bb_session`.
3. Укажите папки загрузок, языки и разрешение по умолчанию, расписание и ratio. Языки выбираются через автокомплит: выбранные значения появляются плашками, крестик убирает язык. Поиск принимает названия и коды (`jap`, `rus`, `English`).
4. В поиске выберите произведение и сезон. Пустой список серий означает весь сезон с добавлением новых эпизодов; можно задать `1, 2, 5–8`.

Контент-провайдеры изначально выключены. Без них задачи сохраняются, а интерфейс сообщает, почему поиск раздач не выполняется. Для живого TMDB нужен пользовательский ключ; для закрытых возможностей Rutracker — пользовательская авторизация.

## Семантика требований

- Языки в интерфейсе показаны названиями. Принимаются также коды и английские названия: `Русский / ru / rus / russian`, `Японский / ja / jap / jpn / japanese`. Все указанные языки аудио обязательны; пустой список снимает ограничение.
- Качество — только разрешение, в пределах минимума и максимума.
- Обязательная фраза — подстрока заголовка/описания без учёта регистра.
- Отсутствующие субтитры не блокируют скачивание. Их языки сохраняются отдельно для будущей интеграции OpenSubtitles.
- Провайдерские списки файлов — подсказки. Worker сопоставляет реальные пути из torrent metadata.
- При неоднозначной нумерации, неизвестном языке или противоречивых сведениях нужна ручная проверка. Абсолютная нумерация аниме автоматически не переводится в сезоны без явного соответствия.
- Нет распознавания языка по звуковому сигналу и проверки синхронизации чужих монтажей. Для внутренних дорожек используются теги контейнера; для внешних — также привязка и язык имени файла.

В «Раздачах» доступны объяснения критериев, выбор кандидата, отклонение и ручное сопоставление видео/дорожек. Ручное исключение относится к конкретной подтаске и ревизии торрента. Подтверждённое противоречие фактическим аудио/качеству после скачивания всё равно запрещает назначать версию текущей.

## Загрузки и расписание

«Готово к просмотру» означает, что доступны начало, конец, первые 32 MiB видео и найденные необходимые внешние дорожки, а ffprobe читает контейнер. Для просмотра нужен внешний плеер с доступом к файлам. Возможны остановки воспроизведения, если плеер догонит загрузку.

«Готово» означает полную загрузку и проверку файлов эпизода; торрент при этом может продолжать сидирование. Ratio хранится на физический торрент, сохраняется между перезапусками. `0` останавливает раздачу после скачивания, пустое значение означает отсутствие лимита. Значение фиксируется при создании загрузки.

Поиск запускается ежедневно во «Время начала поиска» (по умолчанию 00:00) и выполняет полный проход без времени окончания. Завершённый проход сохраняется в БД, поэтому перезапуск не запускает его повторно; незавершённый продолжается. Если приложение было выключено в момент старта, проход начинается при запуске. Часовой пояс берётся из `TZ` (например, `TZ=Europe/Saratov docker compose up -d`), без `TZ` — из `/etc/localtime` хоста. Будущая дата выхода блокирует поиск; неизвестная — разрешает. Дата без времени считается наступившей после окончания соответствующего дня. Загрузки и сидирование работают независимо от расписания.

Улучшение — строго большее разрешение в пределах требований. После проверки новой версии старая раздача останавливается независимо от ratio, когда больше не нужна другим подтаскам. Файлы сохраняются. Пауза одной задачи не останавливает общий торрент, пока он нужен другим активным задачам.

## Плагины и репозиторий

Начальные TMDB/Nyaa/Rutracker входят в образ как файлы. URL публичного каталога проекта пока не задан: укажите собственный HTTPS-каталог в настройках. Для публикации этих же адаптеров:

```bash
python scripts/build_catalog.py --base-url https://your-host.example/lazarr/providers
```

Разместите `catalog.json` и `.py` из `src/lazarr/bundled` по этому адресу; укажите полный URL `catalog.json`. Каталог может находиться в Git-репозитории, если URL возвращает сырые файлы. Поля URL в начальном каталоге — примеры; bootstrap читает локальные файлы и не обращается к ним.

Плагины — доверенный Python-код, исполняемый в процессе Lazarr. Контрольная сумма проверяет целостность относительно доверенного каталога; это не песочница. Секреты и cookies шифруются ключом `/data/secret.key`; резервная копия должна сохранять ключ вместе с БД. Сами torrent metadata могут содержать приватные tracker passkeys и хранятся с ограниченными правами.

Подробнее: [архитектура](docs/architecture.md), [SDK провайдеров](docs/plugins.md), [проверки](docs/testing.md).

## Разработка и тесты

```bash
nix develop
pytest -q
ruff check src tests scripts
ruff format --check src tests scripts
npm ci
npm run test:ui
node --check src/lazarr/static/app.js
```

Тесты swarm используют только loopback и синтетические медиа, без публичных трекеров. Без libtorrent или ffmpeg соответствующие тесты пропускаются с объяснением; полный приёмочный прогон выполняйте в Nix-окружении.

Миграции применяются при запуске. Также доступно `lazarr migrate`. OpenAPI: `/docs`, схема: `/openapi.json`; все прикладные API требуют сессии, изменения — заголовка `X-CSRF-Token`.

## Cloudflare / FlareSolverr

Для защищённых страниц Rutracker предусмотрен отдельный необязательный сервис:

```bash
docker compose --profile cloudflare up -d --build
```

Lazarr обращается к `http://flaresolverr:8191` внутри сети Compose; порт FlareSolverr наружу не публикуется. В настройках Rutracker можно указать другой адрес. Для локального запуска задайте `LAZARR_FLARESOLVERR_URL=http://127.0.0.1:8191` либо поле провайдера. FlareSolverr нужен только при обнаружении проверки Cloudflare. Cookies и User-Agent браузера сохраняются в зашифрованной сессии провайдера; затем Lazarr повторяет исходный запрос. HTML можно получить через браузер, torrent-файлы и CAPTCHA-изображения скачиваются как двоичные данные. Неуспешная проверка приводит к понятной ошибке и паузе в 5 минут.

FlareSolverr запускает Chromium и потребляет дополнительную память. CAPTCHA самого трекера остаётся отдельным шагом входа. Механизм проверен на Rutracker, но результат зависит от текущей защиты сайта. [Документация FlareSolverr](https://github.com/FlareSolverr/FlareSolverr).

## Обложки и нумерация аниме

Обложки TMDB загружаются через авторизованный endpoint Lazarr и сохраняются в `/data/posters`. Браузеру не нужен прямой доступ к `image.tmdb.org`. В настройках TMDB есть отдельное поле «URL изображений» с размером, например `https://image.tmdb.org/t/p/w342`. Переопределение API URL не меняет адрес изображений.

TMDB иногда объединяет несколько телевизионных сезонов в один непрерывный список. Если TMDB предоставляет однозначную группу `Seasons`, форма предлагает обычные сезоны отдельно от исходной нумерации TMDB. Задача сохраняет выбранную схему, а `Episode` остаётся каноническим: разные варианты нумерации используют одни эпизоды. Обновление целого сезона добавляет только эпизоды выбранного сезона.

Проверенный пример: **Re:Zero, TV-2, часть 2** — выбрать «Сезон 2 · 25 серий», серии `14–25`. В TMDB это сезон 1, серии `39–50`. Worker использует явную связь из группы TMDB, а не вычисляет смещение по размеру пакета. Файлы с неоднозначной нумерацией или неподтверждённым языком требуют ручного выбора.

Новые версии встроенных плагинов активируются автоматически. При запуске и каждый час Lazarr проверяет настроенный HTTPS-каталог; при недоступности сети использует локальные копии. Выполняющиеся вызовы заканчиваются на прежней версии. Иконка **Revert** сбрасывает поля конфигурации провайдера к значениям по умолчанию; изменения, включая очистку секретов, применяются кнопкой «Сохранить».

В NixOS FlareSolverr можно запустить отдельно из закреплённого nixpkgs:

```bash
HOST=127.0.0.1 PORT=8191 LOG_LEVEL=warning LOG_HTML=false nix run .#flaresolverr
```

## Удаление задач

Кнопка «Удалить» открывает диалог с отдельным переключателем удаления медиа и загрузок. По умолчанию файлы сохраняются, загрузка без потребителей останавливается. При включённом переключателе удаляются все версии, принадлежащие только этой задаче; общие загрузки сохраняются, пока нужны другим задачам. Канонические Media/Season/Episode остаются независимыми от задач. Очистка файлов фиксируется в БД и повторяется при ошибке или перезапуске; пути с подменой через symlink отклоняются.

## Запуск очереди и наблюдение за поиском

При создании задачи запрос на поиск сохраняется в той же транзакции. Worker начинает его сразу, независимо от ежедневного расписания; интерфейс открывает «Загрузки». Если Worker занят, новая задача ожидает своей очереди без задержки ответа API создания. Паузы, даты выхода, ограничения провайдеров и общие загрузки сохраняют своё действие.

Кнопка «Запустить очередь» запускает поиск всех подходящих незавершённых задач, включая задачи, для которых запланирована следующая попытка. Повторные нажатия во время ожидания объединяются. Запросы переживают перезапуск. Если провайдеры выключены, очередь ждёт их включения.

Во вкладке «Загрузки» видны текущий провайдер и запрос, страница результатов, проверка описания, получение торрент-структуры, сопоставление файлов и передача в загрузку. Прогрессбар показывает завершённые группы запросов, отдельный счётчик — проверенные уникальные кандидаты. Раздел «Ход поиска» содержит последние 40 действий текущего прохода. История действий хранится в памяти; сама очередь — в SQLite.

Для тестов интерфейса используется Node.js с jsdom (`npm ci && npm run test:ui` внутри `nix develop`). Node.js не нужен при запуске Lazarr или в Docker.

В отчёте поиска отдельно показан каждый контент-провайдер: выключен, ожидает, выполняет поиск, проверяет кандидатов, завершил или вернул ошибку. Временная пауза показывает исходную ошибку и время разрешённого повтора. Если ни один поисковый запрос не был успешным, проход обозначается «Поиск не выполнен». Ошибка одного включённого провайдера не прерывает поиск по остальным.

В настройках контент-провайдеров стрелки ↑/↓ задают порядок включённых провайдеров: верхний опрашивается первым. Порядок сохраняется сразу и переживает перезапуск; уже начатая группа запросов заканчивается в прежнем порядке. Ошибка или временная пауза одного провайдера не мешает опросить следующий. Порядок опроса не отменяет сравнение качества найденных кандидатов.

Между исходящими HTTP-запросами к одному контент-провайдеру выдерживается минимум 2 секунды, в том числе между отдельными вызовами плагина. Повторные ручные запуски в пределах 2 секунд объединяются; первая команда и создание новой задачи не задерживаются. После HTTP 429 и ошибок доступности пауза растёт от 1 минуты до 1 часа. `Retry-After` (секунды или HTTP-дата) задаёт минимальный срок ожидания и может увеличить его. Пауза и число последовательных ошибок сохраняются в БД; ручная проверка провайдера не обходит паузу. HTTP 504 означает ошибку доступности, а не подтверждённый rate limit ресурса.

Поиск сохраняет основное написание названия, затем при незакрытых требованиях пробует перечисленные в метаданных варианты его пунктуации и пробелов. Случайные переводы из списка aliases не подставляются: например, для Re:Zero используются `Re:Zero`, `Re Zero`, `ReZero`. Каждый вариант ограничен тремя страницами; в журнале показываются фактический текст и смещение запроса. Rutracker передаёт категорию из выдачи для предварительного отбора. Явно неподходящие типы материалов, сезоны и разрешения отсеиваются до чтения темы, обязательная фраза и полные заявления об аудио — до получения torrent. Неизвестные сведения сохраняют кандидата для дальнейшей проверки.

Worker проверяет перспективные кандидаты первыми и отслеживает покрытие эпизодов в текущем проходе. После подтверждённого покрытия равное разрешение улучшением не считается; неизвестное или более высокое разрешение проверяется до максимума задачи. Год выпуска сезона сопоставляется с датами эпизодов и явной нумерацией сезона, а не только с годом начала сериала. Фактическая проверка файлов остаётся обязательной.

При паузе провайдера обработка его оставшихся кандидатов и страниц прекращается. В SQLite сохраняется отложенный запрос задач для этого провайдера; остальные провайдеры продолжают работу. После паузы поиск повторяется без кэша выдачи, описаний или результатов проверки. Счётчики различают найденных, отсеянных, проверенных, отложенных кандидатов и ошибки проверки. Отложенное количество относится к уже полученной странице, не к неизвестному размеру всей выдачи.

Очередь эпизодов внутри торрента управляется явно: скачиваются первая незавершённая серия и связанные с ней дорожки; файлы следующих серий временно имеют приоритет 0. После завершения текущей серии очередь продвигается независимо от физического порядка файлов в раздаче. Уже полученные данные сохраняются. Начало и конец текущего видео получают piece deadlines, остальная часть скачивается последовательно. Небольшое количество данных соседнего файла может попасть в общий пограничный piece.

## Библиотеки

Вкладка «Библиотеки» содержит три автоматических раздела: «Сериалы», «Кино», «Аниме». Произведение показывается один раз независимо от числа задач и пользователей. Аниме определяется по жанру Animation (TMDB 16) и стране JP либо исходному языку ja; остальные произведения распределяются по типу movie/tv. Японское название само по себе не означает аниме. Недостающие признаки старых записей дополняются из метаданных при открытии библиотек; при недоступности провайдера локальные записи остаются доступны, с отметкой об уточнении классификации. Это логические разделы, они не перемещают файлы на диске.

Карточка произведения показывает описание, обложку, жанры, известные эпизоды с альтернативной нумерацией, календарь дат выхода, последний поиск, версии файлов, качество, встроенные и внешние дорожки и раздачу. Выбранная, текущая и предыдущая версии различаются; непроверенные сведения обозначаются отдельно. Эпизоды без задач или выбранных файлов тоже видны. Последний поиск сохраняется с миграции 0005 при реальной попытке обращения к контент-провайдеру; старые даты не восстанавливаются предположительно. Кнопка «Загрузить субтитры» получает недостающие выбранные языки через включённые провайдеры, сохраняет их рядом с готовым видео и сразу публикует в библиотеке и Jellyfin API. Podnapisi не требует регистрации или ключа. Для OpenSubtitles API key задаётся в «Настройки → Провайдеры субтитров» и хранится зашифрованно.

## Jellyfin-совместимый API

К адресу Lazarr можно подключить Jellyfin-клиент как к серверу. Вход выполняется с учётной записью Lazarr. API предоставляет три библиотеки, произведения, сезоны, загруженные серии, обложки, сведения о воспроизведении, внешние субтитры и прямую HTTP-выдачу файлов с Range-запросами. Позиция, завершённость, число просмотров и время последнего просмотра сохраняются отдельно для каждого аккаунта; незавершённые элементы возвращаются в «Продолжить просмотр».

Воспроизведение доступно только для полностью загруженной и проверенной текущей версии. Приоритет аудио и субтитров берётся из общих значений по умолчанию в настройках Lazarr. Сервер не транскодирует и не перепаковывает медиа: контейнер, видео и встроенная аудиодорожка должны поддерживаться клиентом. Внешние субтитры выдаются отдельным файлом; отдельные внешние аудиофайлы с видео не смешиваются. Маршруты Jellyfin, изменяющие метаданные или библиотеку, не реализованы.
