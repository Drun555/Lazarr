# SDK файловых провайдеров

SDK version: **1.9**. Импорты из `lazarr.sdk`; HTTP через `ProviderContext`, HTML через предоставленный BeautifulSoup. Провайдер экспортирует класс Plugin и использует библиотеки Lazarr, без установки отдельных зависимостей.

## Поставка провайдеров

Все адаптеры находятся в `src/lazarr/providers` и входят в пакет Lazarr. Реестр в `PluginManager.bootstrap()` загружает их напрямую из установленного приложения. Чтобы добавить провайдер, добавьте модуль и зарегистрируйте его в этом реестре. Проверяются контракт класса и совместимость SDK.

Провайдеры и движок поиска обновляются только вместе с Lazarr. Сетевых каталогов, установки отдельных версий и отката плагинов больше нет. Старые файлы в `/plugins` игнорируются; настройки, секреты и сессии провайдеров остаются в базе приложения. Отдельный volume для плагинов не нужен.

Для демонстрации сложных сценариев без сети есть провайдеры-фикстуры в `tests/test_worker.py` и `tests/test_end_to_end.py`.

Kinozal использует настраиваемое зеркало (`https://kinozal.me` по умолчанию), CP1251 для запросов и исходного HTML, UTF-8 для DOM Trawl. Поиск сохраняет оба названия и исходные обозначения сезонов/озвучек. Разбор страницы читает техданные и AJAX-вкладку «Релиз», исключая комментарии и похожие раздачи; языки берутся из явных описаний дорожек, а не из обозначений ДБ/ПМ/СТ. Заявления о дорожках остаются на уровне раздачи. `1 сезон: 1-3 серии из 8` обозначает доступные серии 1–3; общий диапазон серий мультисезонной раздачи не переносится на каждый сезон. При смене зеркала даже сохранённые кандидаты открываются через новый адрес. Torrent-файлы требуют авторизации; при суточном лимите или блокировке двоичного ответа Cloudflare используется infohash этой же раздачи, если Kinozal его возвращает.

## ContentProvider

Файл экспортирует класс `Plugin(ContentProvider)` со свойством `manifest: ProviderManifest`.

Необязательное поле манифеста `comment` (строка, по умолчанию пустая) показывается
сноской внутри раскрытой карточки контент-провайдера в настройках. Допускаются
переносы строк и ссылки `[название](https://example.org)` по HTTP/HTTPS; HTML
отображается как текст. Без комментария сноска не создаётся.

| Метод | Вход | Выход |
|---|---|---|
| `search` | `SearchQuery`, cursor, `offline=False` | `SearchPage` |
| `inspect` | `Candidate`, `offline=False` | Уточнённый `Candidate` |
| `resolve_download` | `Candidate`, `offline=False` | `DownloadSource(torrent=bytes)` или `DownloadSource(magnet=...)` |
| `offline_status` | — | `OfflineStatus`: наличие и годы локального каталога |
| `authenticate` | Словарь вводимых данных | `AuthResult` |
| `auth_status` | — | `AuthResult` |
| `logout` | — | Сброс сохранённого состояния и cookies |
| `healthcheck` | — | Диагностический словарь |
| `close` | — | Освобождение ресурсов |

Методы асинхронные. Поиск не обязан использовать каждое поле запроса, если ресурс не умеет фильтровать по нему. Неизвестные характеристики не должны приводить к безусловному отбрасыванию кандидата.

`SearchQuery` содержит каноническое медиа, названия, внешние ID, сезон, эпизоды и требования. `Candidate` содержит ID/URL, название, описание, размер, seeds, ревизию, внешние ID, `evidence` и `file_hints`. Кандидат не содержит финального сопоставления с подтасками.

## Свидетельства

`Evidence` содержит:

- `field` и `value`, например `audio_languages: ["ru", "ja"]` или `resolution: 1080`;
- `source`: `title`, `description`, `filename`, `structured`, `probe`, `torrent`;
- `excerpt`: исходный фрагмент;
- `scope`: `release`, `file` либо `all_video_files`;
- `file_path` для файловой области;
- `complete`: заявлен ли полный перечень значений;
- `delivery`: `embedded`, `external` или `unspecified` — способ размещения дорожек.

Используйте `all_video_files` только если ресурс явно сообщает одинаковые свойства для каждого видео. Общий список языков сезонной раздачи остаётся `release` и не доказывает наличие каждого языка в каждой серии.

Не подменяйте неизвестное пустым полным списком. Например, отсутствие раздела «Аудио» означает неизвестное значение; явное полное перечисление только английского означает отсутствие русского.

## Авторизация и ошибки

`AuthResult.status`: `anonymous`, `authenticated`, `required`, `challenge`. Провайдер автоматически использует сохранённые учётные данные при работе. Challenge возвращает список полей и необязательное изображение; если Rutracker потребует CAPTCHA, WebUI предложит её при открытии настроек. Rutracker сохраняет скрытые поля CAPTCHA между шагами. Cookies HTTP-клиента сериализуются и шифруются ядром.

Плагин получает настройки через `self.ctx.config`, состояние — `self.ctx.state`, HTTP-клиент — `self.ctx.http`. Используйте `self.ctx.request` для стандартных сетевых ошибок. `base_url(default)` применяет разрешённое переопределение домена.

`ProviderError(code, message, retry_after)` использует коды `configuration`, `auth_required`, `rate_limited`, `unavailable`, `not_found`, `parse_error`. Сообщения не должны содержать токены, пароли или приватные URL. `retry_after` измеряется в секундах.

## MetadataProvider и календарь

`MetadataProvider`: `search(query)`, `get_media(kind, id)`, `get_season(id, number)`. Возвращаются `MetadataItem`, `SeasonInfo`, `EpisodeInfo` с нормализованными названиями, внешними ID и датами. Абсолютный номер эпизода задаётся только при наличии достоверной привязки.

`ReleaseCalendarProvider.release_date(media, episode)` возвращает `ReleaseDate(value, precision, source)`. Начальная реализация использует сведения TMDB. Даты без времени и неизвестные даты имеют разную семантику — см. README.

## Worker и результат

`Worker.evaluate(candidate, subtasks)` получает torrent metadata и возвращает уточнённый кандидат, metadata и `EvaluationReport`. `Matcher.evaluate` — чистый внутренний алгоритм над фактическими файлами.

`EvaluationReport.evaluations` содержит по одному `SubtaskEvaluation` на запрос. В нём: `MATCH/MISMATCH/UNKNOWN`, критерии с причинами и `FileBinding`, если соответствие видео однозначно. `plan` содержит только автоматически подтверждённые bindings.

`FileBinding`: ID подтаски, индекс/путь видео, порядок эпизода, `TrackBinding[]`, разрешение, отсутствующие языки субтитров. Встроенная дорожка не имеет отдельного индекса файла. Внешняя дорожка всегда ссылается на файл того же торрента.

Worker формирует preflight по доступным свидетельствам и отдельную verification после ffprobe. Ручной выбор сохраняет исключение для конкретной подтаски и ревизии; он не превращает заявление провайдера в фактическое доказательство.


## SDK 1.1

`MetadataItem.episode_numbering` содержит явные альтернативные координаты эпизодов: ключ `"1:39"`, значение `[{"season": 2, "episode": 14, "source": "tmdb:episode_group:…"}]`. Основные `Season`/`Episode` не перенумеровываются. `Task.numbering` хранит выбранную пользователем схему и отображаемые номера. Неоднозначные координаты отбрасываются.

`ProviderContext.request(..., browser_html=True)` допускает DOM-ответ Trawl после обнаружения Cloudflare; двоичные запросы должны оставлять флаг выключенным. Для form-urlencoded в CP1251 передайте `browser_form_encoding="cp1251"`: прямой запрос сохраняет исходные байты, браузерный получает UTF-8-представление полей. Адрес решателя берётся из `trawl_url` или `LAZARR_TRAWL_URL`; старые настройки FlareSolverr остаются запасным вариантом. Защищённые cookies и User-Agent принадлежат сессии провайдера.

## SDK 1.2: языки и обновления

`language()` нормализует ISO-2/ISO-3, английские и русские названия, включая прилагательные «Русская», «Японские». Технические строки аудио/субтитров сохраняют исходный текст и размещение дорожки. Обычный список языков остаётся заявлением всей раздачи; дамп MediaInfo одного файла не переносится на весь сезон.

Worker сначала связывает внешний файл с единственным видео по эпизоду/имени. Если описание объявляет один язык всех внешних дорожек данного вида, он может уточнить неопределённый язык связанного файла. Несколько заявленных языков не позволяют выбрать один для безымянного файла. `TrackBinding.language_source` отличает имя файла от описания; предположение из описания не заменяет неизвестный язык при фактической проверке ffprobe.

Revert в WebUI сбрасывает конфигурационные поля провайдера. Версия адаптера определяется сборкой Lazarr.

SDK 1.3 добавляет `SearchQuery.text`: выбранный ядром текст текущего поискового запроса. Контент-провайдер использует его, если он непустой, и применяет собственное кодирование запроса. Пустое значение допускает прежний выбор названия. Файловые плагины Nyaa/Rutracker 1.0.3 требуют SDK >=1.3. Rutracker передаёт `Evidence(field="category", source="structured")` из поисковой строки; это заявление ресурса для предварительного отбора. `SubtaskRequest.air_date` позволяет ядру сопоставлять год эпизода с заявленным годом конкретной части сезона.


## SDK 1.8: метаданные для локального экспорта

`MetadataItem` дополнен `tagline`, `runtime` (минуты), `vote_count`, `end_date`
и `collection_id`. `SeasonInfo` передаёт `id`, `overview`, `poster`, `air_date`,
`community_rating`, `people`; `EpisodeInfo` — `runtime`, `community_rating`,
`vote_count`, `people`. Все новые поля необязательны. Записи `people` могут содержать
`ImageUrl` и `SortOrder` для портретов и порядка актёров. TMDB 1.0.8 требует SDK >=1.8.


## SDK 1.9: оффлайн-каталоги контент-провайдеров

Провайдер объявляет `ProviderManifest(..., offline_capability=True, sdk=">=1.9,<2")`.
При чтении манифеста принимается также `offlineCapability`; API возвращает
`offline_capability`. По умолчанию возможность выключена. Rutracker 1.1.0 поддерживает XML-дампы; другие адаптеры подключают возможность
отдельно. Ядро не задаёт формат архивов.

Lazarr создаёт `downloads/offline/<provider-id>` рядом с `source` и `user`.
Пользователь сам помещает туда файлы. Плагин получает абсолютные пути через
`self.ctx.offline_directories: tuple[Path, ...]`: один путь для общего хранилища,
несколько для отдельных корней фильмов и сериалов. Формат, индексация, чтение и
объединение нескольких каталогов принадлежат провайдеру. Ядро не загружает архивы,
не перемещает и не удаляет их содержимое.

`async offline_status()` проверяет установленные файлы и возвращает, например,
`OfflineStatus(available=True, year_from=2000, year_to=2025)`. Границы включительны:
фильм 2024 года попадает в этот диапазон. `year_from` необязателен, `year_to`
обязателен при `available=True`; диапазон должен быть упорядочен. Когда файлов
нет, возвращается `OfflineStatus(available=False, message="...")`. Сам флаг
в манифесте не означает, что данные уже установлены. Для сериалов учитывается
год запрошенного эпизода, при отсутствии даты — известный год сезона; при
неизвестном годе оффлайн-поиск пропускается.

Провайдер с этой возможностью реализует следующие сигнатуры:

```python
async def offline_status(self) -> OfflineStatus: ...
async def search(self, query, cursor=None, *, offline=False) -> SearchPage: ...
async def inspect(self, candidate, *, offline=False) -> Candidate: ...
async def resolve_download(self, candidate, *, offline=False) -> DownloadSource: ...
```

`offline=True` выбирает локальный источник каталога для всех трёх этапов.
Тот же флаг доступен через `self.ctx.offline`. При `False` используется обычный
источник. Старым провайдерам без возможности оффлайна новый аргумент не
передаётся, поэтому менять их сигнатуры не нужно. Провайдер должен возвращать
собственный ID в `Candidate.provider`; ядро сохраняет происхождение кандидата
в `Candidate.offline`, в том числе для повторной проверки и отчёта об описании.

Оффлайн — источник каталога, а не запрет сети. `resolve_download` может вернуть
как torrent-байты, так и magnet: получение метаданных magnet по сети разрешено.
`ctx.request` и `ctx.http` также доступны с обычными TLS-настройками и интервалами
запросов; при необходимости можно запросить дополнительные сведения по сети.
Контекст получает настройки, секреты и копию сохранённой сессии провайдера.
Изменения этой копии не сохраняются обратно. Открытие локального каталога не
требует авторизации и не блокируется паузой онлайн-поиска; ошибки локального
прохода не перезаписывают онлайн-сессию и не устанавливают сетевую паузу.

При сохранении оффлайн-кандидата `id` и `url` должны указывать на ту же тему
онлайн. Rutracker восстанавливает URL страницы из ID в дампе. Для новых серий
ядро сначала проверяет онлайн темы ранее скачанных серий той же задачи и сезона,
включая найденные через оффлайн. Эта проверка получает свежее описание и источник
загрузки; архивный magnet не переносится в онлайн-кандидата.

Если знакомые темы не покрыли запрос, ядро выполняет полный проход по подходящим локальным каталогам:
поиск, описание, torrent-метаданные и проверка требований. При полном покрытии
задачи онлайн-поиск не запускается. При отсутствии данных, ошибке, неподходящих
файлах или дорожках продолжается поиск остальных кандидатов, затем онлайн.
Подробности порядка и ручных альтернатив — в `search-scoring.md`.

`GET /api/v1/providers/{id}/offline` возвращает текущий `OfflineStatus` и
`directories` (доступ по праву `providers`). Путь также виден в настройках
провайдера; хранилище показывает общий каталог `offline`. Пример адаптера
с собственным тестовым форматом и проверки контракта: `tests/test_offline.py`.


### Rutracker: XML и XML.XZ

Провайдер Rutracker поддерживает дампы с корнем `<torrents>`: каждая запись
`<torrent id="..." size="..." registred_at="...">` содержит `title`, вложенный
`torrent hash="..."`, `forum`, BBCode в `content` и дерево `dir` / `file`.
Поддерживаются `.xml` и `.xml.xz`, включая несколько последовательных XZ-потоков.

Поместите файл, например `rutracker-20260927.xml.xz`, в
`downloads/offline/rutracker`. Распаковывать его заранее не нужно. Если найдено
несколько полных снимков, выбирается самый новый по дате `YYYYMMDD` в имени
среди всех настроенных корней. При одинаковой дате готовый `.sqlite3` имеет
приоритет над XML; затем сравниваются время изменения и путь.
Для файла без даты год покрытия определяется по самой поздней дате регистрации
раздачи после явной подготовки через CLI. Проверка статуса не запускает импорт.
Если дата пока неизвестна, оффлайн-проход не объявляет покрытие: назовите файл
с датой снимка или заранее подготовьте индекс. Год снимка включается целиком; отсутствие
позднего релиза в неполном году приведёт к обычному онлайн-поиску.

При первом поиске создаётся индекс в `offline/rutracker/.lazarr-index`.
Импорт читает XML последовательно, хранит в памяти одну раздачу, сжимает
описания и списки файлов; полный XML на диск не распаковывается. В индекс
попадают раздачи с видео, включая образы дисков и редкие контейнеры. Раздачи
без списка файлов тоже сохраняются; известные раздачи без видео (музыка, книги,
программы) пропускаются. Поддержку формата и блокеры затем проверяет обычный
поисковый поток. Для большого
архива первый проход может занять несколько минут и потребовать дополнительного
места под индекс. Импорт выполняется вне основного цикла приложения. В журнале
появляются начало, каждые 100 тысяч записей и завершение импорта.

Последующие запросы используют полнотекстовый индекс названий SQLite, без
повторного чтения архива. Все слова текущего запроса должны присутствовать в
названии; регистр и различие `ё` / `е` игнорируются. Ядро перебирает варианты
названий и затем проверяет идентичность, сезон и остальные требования.
Индекс автоматически перестраивается при замене/изменении исходного файла или
версии формата кэша. Одновременные запросы ждут один импорт. Незавершённый или
повреждённый импорт не публикуется и не подменяет прежний индекс; устаревший
индекс для изменившегося архива не используется. Исходный архив не изменяется.
Каталог `.lazarr-index` — восстанавливаемый кэш; его можно удалить при остановленном
Lazarr, чтобы освободить место или принудительно переиндексировать данные.

Чтение описания снимает BBCode, сохраняя строки MediaInfo и заголовки спойлеров.
Категория, языки и IMDb ID поступают из дампа; неизвестное число сидов не
выдумывается. Дерево `dir` / `file` даёт только `file_hints`, а не окончательное
подтверждение файлов. `resolve_download(..., offline=True)` возвращает magnet по
infohash из выбранного снимка, с четырьмя трекерами `bt.t-ru.org`, `bt2.t-ru.org`,
`bt3.t-ru.org`, `bt4.t-ru.org` по HTTP на `/ann?magnet`. Ссылки формируются при
чтении каталога: перестраивать существующий SQLite-индекс не нужно.
Libtorrent получает реальные метаданные по сети, опрашивает трекеры и использует
известные DHT-узлы основной сессии (либо сохранённую таблицу). Отдельная сессия
получения метаданных имеет собственный DHT ID; ожидание ограничено 120 секундами.
Трекеры сохраняются и в полученном `.torrent` для последующей загрузки.
Для чтения дампа и выдачи magnet логин, cookies и Trawl не требуются. Если
метаданные недоступны или раздача не подходит, поиск продолжится по обычным правилам.
Онлайн-режим Rutracker с авторизацией и загрузкой `.torrent` сохранён.


### Подготовка для слабых систем

Самый экономный вариант — построить переносимый каталог на другом компьютере:

```bash
lazarr prepare-rutracker /path/rutracker-20260927.xml.xz \
  --output /path/rutracker-20260927.sqlite3
```

Готовый `.sqlite3` переносится в `downloads/offline/rutracker` на сервере.
Он самодостаточен: исходный XML/XZ, старый каталог кэша и совпадение путей или
inode не нужны. Поиск читает небольшие страницы SQLite и распаковывает описание
только выбранной темы. На одном диске экспорт использует жёсткую ссылку на
неизменяемый готовый индекс, если файловая система это позволяет; при копировании
на другой диск переносится полный самостоятельный файл. Существующий файл
назначения команда не перезаписывает.

Эту же команду можно запустить непосредственно на слабом сервере. По умолчанию
её процесс получает пониженный приоритет (`nice=10`, настраивается `--nice 0..19`),
работает последовательно, использует кэш SQLite 8 МиБ и выдаёт распакованный XML
порциями до 64 КиБ. Предел заявленной памяти декодера LZMA — 2 ГиБ; это защитная граница,
а не обещание малого потребления RAM при распаковке. Некоторые реальные дампы
объявляют словарь 1 ГиБ. Для машин с недостаточной памятью используйте готовый
`.sqlite3`, подготовленный на другом компьютере: при поиске LZMA не запускается. Полный объём XML в RAM или на диске не размещается.
При автоматическом поиске подготовка выполняется вне основного цикла приложения;
запрос ждёт готовности каталога, сохраняя приоритет оффлайна перед онлайном.

Для многопоточных XZ-дампов импорт сохраняет контрольные точки на границах
независимых потоков, **только если граница находится между целыми XML-записями**.
Смещение, записи и поисковый индекс фиксируются одной транзакцией SQLite WAL.
Остановка поиска, Ctrl+C или перезапуск сохраняют завершённую часть в `.building`.
Следующий запуск продолжает чтение с сохранённого сжатого смещения, не распаковывая
предыдущую часть. Если запись пересекает границу потоков, эта граница пропускается.
Однопоточный XZ или обычный XML читается последовательно; без безопасной контрольной
точки прерванный импорт начнётся заново. Готовый переносимый индекс подходит и
для таких архивов.

Незавершённый индекс не участвует в поиске и не экспортируется. После окончания
импорта WAL переносится в основной файл, и готовый каталог публикуется атомарно.
В настройках Rutracker кнопка «Проверить каталог» показывает готовность, количество
записей либо сохранённый процент подготовки по сжатому смещению. Проверка не
требует авторизации на форуме и не начинает переиндексацию.


### Живой прогресс индексации

Реальная подготовка индекса регистрируется отдельной задачей «Индексация
оффлайн-каталога» в окне «Процессы». Показываются имя архива, текущая фаза,
процент прочитанных байтов, обработанные раздачи и число раздач в индексе.
Прогресс обновляется внутри XZ-потока, а не только на контрольных точках.
До завершения публикации индекса значение не достигает 100%; ETA не рассчитывается.
Снимки прогресса записываются не чаще раза в секунду, кроме смены состояния;
открытое окно обновляется штатным опросом раз в 1,5 секунды.

Задачи создаются и при поиске, и при `prepare-rutracker`. Для отображения CLI-задачи
команда должна использовать тот же каталог данных Lazarr (`LAZARR_DATA_DIR` или
глобальный `--data-dir` перед именем команды). Индексировать можно архив вне папки
загрузок. CLI не открывает базу приложения: общий реестр статусов находится
в `data/background-jobs`. В SDK его путь доступен как `ctx.background_directory`.

Готовый индекс повторно не регистрируется как работа. Несколько запросов,
ожидающих один импорт, видят одну задачу. Завершение, ошибка и остановка переходят
в недавние задачи; аварийно завершившийся процесс определяется по освобождённой
блокировке и показывается как «Прервано». Возобновлённый импорт начинает новую
задачу с прогрессом последней сохранённой контрольной точки. Для каждого каталога
хранится последняя попытка; интерфейс показывает до 30 недавних завершённых попыток.
