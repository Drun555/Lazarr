# Файлы загрузок и пользовательская медиатека

В стандартном хранилище `/downloads` Lazarr создаёт две папки:

```text
source/<infohash>/<оригинальные пути раздачи>
user/Series/Название (2024)/Season 01/Название - S01E01 - Эпизод.mkv
user/Series/Название (2024)/Season 01/Название - S01E01 - Эпизод.ru.7.srt
user/Movies/Название (2025)/Название (2025).mkv
user/Movies/Название (2025)/movie.nfo
user/Movies/Название (2025)/poster.jpg
user/Anime/Название (2024)/tvshow.nfo
user/Anime/Название (2024)/Season 01/Название - S01E01 - Эпизод.mkv
user/Anime/Название (2024)/Season 01/Название - S01E01 - Эпизод.nfo
```

`source` содержит настоящие файлы, включая незавершённые загрузки. `user`
содержит NFO, изображения и относительные символические ссылки на проверенные
видео и связанные внешние дорожки. Ссылки появляются уже при статусе «Готово к просмотру»,
когда буфер готов, даже если файл ещё скачивается. Дополнительного места под копии видео не нужно.
Номер в имени внешней дорожки различает несколько дорожек одного языка.

В настройках показываются фактические пути и ошибки хранилища. Существующие
значения путей, заканчивающиеся на `movies` или `series`, считаются старой
схемой: `source` и `user` располагаются рядом с ними. Можно указать сам корень,
например `/downloads`, в обоих полях. Произвольный путь или отдельная точка
монтирования используется как самостоятельное хранилище со своими `source` и
`user`. Смена настройки определяет место новых загрузок; она не переносит уже
скачанные файлы на другой диск.

## Восстановление и удаление

Lazarr поддерживает `user` автоматически: при старте и примерно раз в 30 секунд
восстанавливает отсутствующие ссылки, исправляет их цели и удаляет устаревшие.
Ссылки также создаются сразу после успешной проверки готового к просмотру медиа. Если оригинал
исчез, ссылка снимается, а проблема появляется в настройках. Когда оригинал
возвращается, ссылка восстанавливается. Приложение не восстанавливает утраченные
байты видео из символической ссылки.

Для одного эпизода публикуется первая подтверждённая версия. При конфликте
человеческих имён используется правило «кто первый — того и тапки», включая
сравнение без учёта регистра. Чужие файлы и ссылки не перезаписываются.

Удаление ссылки вручную не удаляет оригинал: Lazarr восстановит ссылку.
Редактирование содержимого **через ссылку** изменяет оригинальный файл и может
повредить раздачу. Для удаления медиа используйте интерфейс Lazarr: ссылки
убираются до удаления исходников. Удаление задачи с сохранением медиа сохраняет
и пользовательскую медиатеку. При явном выборе нового релиза действует прежняя
логика замены: старый выбор снимается, новая ссылка появляется после проверки
нового файла.

## Переход со старой структуры

При первом запуске после обновления Lazarr переносит зарегистрированные папки
`movies/<infohash>` и `series/<infohash>` в `source/<infohash>` **до** добавления
торрентов в движок. Содержимое раздач и индексы файлов не меняются. Новый путь
передаётся движку вместе с сохранённым состоянием загрузки.

Операция имеет журнал в БД: перезапуск после перемещения папки, но до сохранения
нового пути продолжает миграцию. Обновляются также пути отложенной очистки.
Используется переименование внутри файловой системы; скрытого копирования
терабайтов между дисками нет. Коллизия папок, недоступный источник или ошибка
перемещения останавливают восстановление торрентов; ошибка видна в настройках,
WebUI остаётся доступен. После устранения причины попытка повторяется.
Посторонние и не зарегистрированные в БД файлы не перемещаются и не удаляются.

## Docker Desktop, Windows и WSL2

Монтируйте **весь корень хранилища**, а не один `user`. Например, другой
медиасервер может получить `/путь/Downloads:/media:ro`: внутри него должны быть
доступны и `/media/source`, и `/media/user`. Относительные ссылки продолжат
работать при смене абсолютного пути общего корня.

Для Docker Desktop с WSL2 рекомендуем каталог на Linux-файловой системе WSL,
например `~/lazarr-downloads`, с запуском Compose из WSL:

```bash
LAZARR_DOWNLOADS="$HOME/lazarr-downloads" docker compose up -d
```

Docker рекомендует Linux-файловую систему также для производительности:
https://docs.docker.com/desktop/features/wsl/best-practices/

Папка на `C:`/`D:`, доступная контейнеру через bind mount, и Linux-файловая система
WSL могут по-разному поддерживать симлинки. Lazarr проверяет создание и чтение
относительной ссылки на самом диске; при ошибке показывает рекомендацию сменить
хранилище. Он не подменяет ссылки копиями или Windows `.lnk`-ярлыками.

Успешная проверка внутри Linux-контейнера не гарантирует чтение Linux-симлинков
любым Windows-плеером или через SMB. Для воспроизведения используйте
медиасервер в Linux/WSL с доступом к обоим каталогам. Доступ из конкретного
Windows-приложения или SMB-клиента нужно проверить на своей конфигурации.


## Локальные метаданные и Jellyfin

Lazarr сохраняет `movie.nfo`, `tvshow.nfo`, `season.nfo` и NFO с именем каждого
эпизода. Они содержат названия, описания, даты, идентификаторы провайдеров,
жанры, участников и рейтинги, если эти данные доступны. Нумерация эпизода в NFO
совпадает с именем опубликованного файла, включая альтернативную нумерацию.
Обложки сохраняются как `poster`, фоны как `fanart`, кадры эпизодов как
`<имя видео>-thumb` с расширением исходного изображения. Изображения TMDB
скачиваются через настроенный URL изображений провайдера и локальный кэш.
Неизвестные источники изображений отражаются как ошибка в настройках хранилища.

TMDB также передаёт постер, описание, дату премьеры, ID и рейтинг каждого сезона;
постер сохраняется в `Season XX/poster.<расширение>`. Для эпизодов сохраняются
длительность, рейтинг, число голосов, актёры (включая приглашённых), режиссёры и
сценаристы. Для фильмов и сериалов экспортируются слоган, ключевые слова, трейлеры
YouTube в формате Kodi, портреты и порядок актёров; для фильмов — длительность и
ID коллекции, для завершённых сериалов — дата последнего выхода.
Длительности берутся из TMDB в минутах, а не подменяют технические данные видео.

Миграция `0016` сохраняет расширенные данные сезонов и эпизодов в БД и ставит
ранее сохранённые сезоны на фоновое обновление. Старые карточки произведений
дополняются автоматически; ручные названия и нумерация сохраняются. Недоступные
поля не записываются в NFO. При альтернативной нумерации обложка и ID канонического
сезона не назначаются другому экспортируемому сезону. Наличие метаданных в БД
не создаёт файлов для нескачанных эпизодов или спешлов.

NFO обновляются вместе со ссылками. Изображения обрабатываются отдельной фоновой
задачей примерно каждые 30 секунд. Ошибка сети сохраняет прежнее изображение и
не препятствует публикации видео; следующая попытка происходит автоматически.
Файлы записываются атомарно; неизменившиеся NFO и изображения не перезаписываются.
Lazarr управляет только путями из своего журнала: чужие файлы не присваиваются.
Редактировать управляемые NFO вручную не следует — экспорт обновит их из БД.

Аниме-сериалы определяются так же, как в WebUI: жанр Animation и страна Япония
либо исходный японский язык. Они публикуются в `Anime`; аниме-фильмы остаются
в `Movies`, чтобы не смешивать типы библиотек. При изменении классификации
старые управляемые ссылки и метаданные убираются, новые создаются в нужном
каталоге. Оригиналы раздач не перемещаются.

Монтируйте весь корень хранилища в Jellyfin, например `/mnt/user/library:/media:ro`.
Создайте три библиотеки:

- Фильмы: `/media/user/Movies`, тип Movies.
- Сериалы: `/media/user/Series`, тип Shows.
- Аниме: `/media/user/Anime`, тип Shows.

База и кэш Jellyfin должны иметь отдельный доступный для записи каталог.
Включите сканирование библиотек в Jellyfin; при необходимости запустите его
вручную. Локальные NFO читаются штатно. Чтобы метаданными управлял только Lazarr,
отключите удалённые загрузчики метаданных и изображений, а также NFO saver в этих
библиотеках. Клиенты, права доступа, прогресс просмотра и транскодирование теперь
настраиваются на стороне Jellyfin. Готовые к просмотру незавершённые загрузки также экспортируются; доступность
перемотки зависит от уже скачанных частей файла и поведения плеера.

Старые таблицы прогресса и плейлистов сохранены в SQLite как архив; новый код их
не использует и не переносит в Jellyfin. Миграции БД сохранены для обновления
существующих установок. Удалённые клиентские маршруты Lazarr возвращают 404.

### Порядок показа спецэпизодов

Для сезона 0 Lazarr рассчитывает место спецэпизода по дате выхода относительно серий обычных сезонов: перед первым сезоном, после завершившегося сезона или перед следующей серией внутри сезона. Если дата отсутствует или совпадает с датой обычной серии, позиция остаётся незаданной. Даты обычных сезонов загружаются даже без их выбора для скачивания и кэшируются на сутки.

В сопоставлении файлов сезона спецматериалов четвёртая колонка «Порядок показа» позволяет выбрать «До сезона», «После сезона» или «До конкретного эпизода», указать сезон и при необходимости эпизод. «Не задано» отключает позицию, а «По дате выхода» возвращает автоматический расчёт. Ручная позиция сохраняется независимо от обновлений метаданных.

В NFO эпизода экспортируются `airsbefore_season`, `airsafter_season` и `airsbefore_episode`; после сохранения сопоставления NFO обновляются. Для обычных сезонов эти поля не выводятся.
