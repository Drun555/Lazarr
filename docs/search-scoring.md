# Оценка раздач

Алгоритм находится в `src/lazarr/_search_builtin/selection.py`: `SCORE_WEIGHTS`,
`STAGE_THRESHOLDS`, `assess_candidate`. Lazarr исполняет этапы, хранит отчёты и
предоставляет ручной выбор. Новый отчёт требует SDK 1.7; старые движки продолжают
работать без баллов через совместимый интерфейс.

## Локальные каталоги перед онлайн-поиском

Для провайдеров с `offline_capability=True` сначала проверяется наличие
установленных данных и диапазон годов из `offline_status()`. Для фильма берётся
год фильма, для сериала — год искомого эпизода или известный год сезона.
При неизвестном годе или выходе за границы каталога используется онлайн-поиск.
В запрос к каталогу попадают только эпизоды, годы которых он покрывает.

После приоритетного обновления ранее выбранных тем все подходящие локальные
каталоги проходят поиск прежде, чем начнётся общий онлайн-поиск. Для локальных данных читаются
все варианты запросов и все страницы, без онлайн-лимитов в три страницы и
12 подробных проверок. Кандидаты объединяются в очередь по убыванию оценки
заголовка; каждый проходит описание и сразу проверку файлов. Повторяющийся
курсор страницы считается ошибкой каталога.

Первый полностью подходящий вариант закрепляется за каждой подтаской.
Когда найдены все искомые серии и запрошенные дорожки, дальнейший поиск
прекращается. Иначе начинается обычный онлайн-проход, сохраняя уже найденные
варианты. Ошибка или отсутствие локальных данных также допускает онлайн-поиск.
Одна и та же тема может повторно проверяться онлайн: архивная версия могла
не содержать нужные серии. Отключённые провайдеры не участвуют ни в одном проходе.

Флаг `offline` означает источник каталога, а не отсутствие сетевого доступа:
magnet может получать метаданные по сети, а провайдер — делать HTTP-запросы.
Ручной поиск альтернатив просматривает оба источника даже после успешного
оффлайн-прохода и сам не запускает загрузку.

## Этапы

1. **Заголовок**, порог 20. Строится короткий список. Варианты запросов и страницы
   онлайн просматриваются до ограничения: до трёх страниц на вариант запроса.
2. **Описание**, без минимального балла (в отчёте порог 0). В онлайн-проходе до 12 лучших кандидатов
   каждого провайдера объединяются в общую очередь по убыванию оценки заголовка.
   Для каждого кандидата сразу после описания проверяются файлы. Только явные
   блокеры, включая BDMV, запрещают получение torrent-метаданных. Названия и годы из
   описания читаются из подписанных полей, не из случайных упоминаний в сюжете.
3. **Файлы**, порог 100. Сопоставляются реальные файлы torrent-метаданных,
   проверяются эпизоды, качество и доступные сведения о дорожках. Фактическая
   проверка кодеков/дорожек после загрузки остаётся обязательной.

Оценка каждого этапа пересчитывается, а не добавляется к предыдущей.
Внутри каждой группы учитывается одно сильнейшее подтверждение. Повтор названия
в нескольких местах не увеличивает оценку. На третьем этапе заявленное наличие
серии заменяется результатом проверки файлов.

К оценке добавляются предпочтения пользователя: за разрешение в разрешённом
диапазоне начисляется 5 / 10 / 20 / 40 / 60 / 80 / 100 баллов для
480 / 576 / 720 / 1080 / 1440 / 2160 / 4320p соответственно. Каждый запрошенный
язык аудио или субтитров даёт +20 при наличии подтверждения. На первом этапе
учитываются заявления заголовка, на втором — также сведения описания, на третьем —
разрешение и дорожки сопоставленного файла. Повторные заявления одного языка
не увеличивают балл. Незапрошенные языки бонуса не дают.

Баллы предпочтений определяют порядок проверки, но не заменяют подтверждение
произведения: пороги 20 и 100 на этапах заголовка и файлов должны быть пройдены
баллами идентичности, сезона и эпизода. В отчёте недостаток этих подтверждений
указывается отдельной блокирующей причиной.

## Ключевые слова задачи

В создании и редактировании задачи, а также в требованиях по умолчанию можно
задать до 50 правил вида «слово или фраза → баллы». Баллы — целые числа
от −10000 до +10000, по умолчанию +50. Например, `DUB Studio → +50`,
`CAMRip → −100`. Пустые и повторяющиеся без учёта регистра фразы запрещены.

Совпадение ищется как подстрока без учёта регистра: на первом этапе в заголовке,
на втором и третьем — в заголовке и описании. Каждое правило применяется один
раз за этап, даже если слово повторяется или найдено в обоих источниках.
Отсутствие слова даёт 0 баллов. Совпавшие правила складываются, включая штрафы;
причина и источник каждого начисления доступны в отчёте раздачи.

Это предпочтения, а не обязательные фильтры: отрицательная итоговая оценка сама
по себе не запрещает подходящую раздачу и не отменяет подтверждённые требования.
Баллы заголовка определяют очередь чтения описаний. Совпадения, обнаруженные
только в описании, уточняют оценку при проверке кандидата; правило остановки на
первом полностью подходящем варианте сохраняется.

Старое поле `keyword` при обновлении данных задач и настроек переносится в
`keywords: [{"text": "прежняя фраза", "points": 50}]`. API также принимает старое
поле для совместимости. При явно переданном `keywords`, включая пустой список,
используется новый список. Новые данные сохраняются без старого поля.

| Группа | Признак | Баллы |
| --- | --- | ---: |
| Идентичность | Совпали внешние ID | +120 |
| Идентичность | Собственное имя сезона и год | +90 |
| Идентичность | Имя сериала/алиас и подходящий год | +70 |
| Идентичность | Только имя | +20 |
| Сезон | Совпал номер сезона/показа | +30 |
| Сезон | Номер расходится | −10 |
| Эпизод, этапы 1–2 | Заголовок заявляет нужный эпизод | +10 |
| Эпизод, этапы 1–2 | Заголовок не заявляет нужный эпизод | −10 |
| Эпизод, этап 3 | Эпизод подтверждён файлами | +60 |
| Эпизод, этап 3 | Файлы явно содержат другие эпизоды | −20 |
| Эпизод, этап 3 | Нумерацию определить не удалось | 0 |

## Противоречия и выбор

Порог сам по себе не разрешает автоматическую загрузку: все обязательные
критерии должны быть подтверждены. Несовместимый тип содержимого, конфликт ID,
нарушение требований и явная чужая нумерация остаются блокирующими.
Ненумерованные `[TV]` / `[ТВ]` учитываются как `TV-1`. Совпадение номера показа
даёт +30 баллов, несовпадение −10 и само по себе не блокирует кандидата.
Одиночный `TV-N` может обозначать порядок показов: подтверждённые имя сезона
и год сильнее этой пометки. Также подходит точный алиас сериала с годом
запрошенного сезона, если известные сезоны не делают этот год неоднозначным. Явные сезоны в файлах и нумерация из метаданных
не переписываются эвристикой.

Для каждой подтаски сохраняется первый кандидат, полностью прошедший проверку
и содержащий все запрошенные языки аудио и субтитров. Если кандидат не подошёл,
проверяется описание следующего в очереди. Когда покрыты все искомые подтаски,
дальнейшие подробные проверки прекращаются. Предел 12 подробных проверок
действует отдельно для каждого провайдера в онлайн-проходе. Ручной поиск альтернатив проверяет
весь ограниченный набор и не запускает загрузку автоматически.

Если вариантов со всеми субтитрами нет, сохраняется прежнее поведение:
субтитры необязательны, и среди кандидатов с подтверждёнными обязательными
критериями выбирается максимальная итоговая оценка. При равенстве сравниваются
разрешение, отсутствующие субтитры, сиды, размер и стабильные идентификаторы.

Если автоматического кандидата нет, пригодные для ручного выбора раздачи
сохраняются. Лучшая показывается как рекомендуемая, подтаска переходит в
`needs_selection`. Когда файлы не сопоставлены, интерфейс пишет «Требуется
сопоставление файлов». Отсутствие серии блокирует автоматический выбор,
но пользователь может явно указать видеофайл. До подтверждения никакая
загрузка не начинается. Отклонённые пользователем раздачи не рекомендуются.

Отчёт хранит баллы, источники, пороги и блокирующие причины отдельно по этапам;
карточка раздачи раскрывает их через «Оценка: … баллов · почему».

## Приоритет ранее выбранных тем

В самом начале поиска, до оффлайн-каталогов и общего онлайн-поиска, Lazarr
обновляет темы, связанные с текущими файлами
выполненных подтасок той же задачи и сезона. Каждая тема проверяется один раз:
читаются актуальные заголовок, описание и torrent-метаданные. Старый состав
файлов не считается подтверждением наличия новой серии.

Это относится и к раздачам, найденным в оффлайн-каталоге: сохраняются ID
и онлайн-ссылка темы. При появлении новой серии эта тема открывается с
`offline=False`; старые magnet и ссылка скачивания не используются. Отдельная
дублирующая запись раздачи не нужна. Если знакомые темы не покрывают запрос,
поиск продолжается по локальным каталогам, затем онлайн.

Такие темы проверяются по убыванию баллов заголовка. Если они покрывают все искомые
серии, проходят обязательные критерии и содержат все запрошенные субтитры,
оставшиеся темы и общий поиск пропускаются. Иначе
выполняется обычный поиск с сохранением уже проверенных вариантов и без
повторной проверки тех же тем. Ручной поиск альтернатив всегда продолжает
общий поиск. Отключённые провайдеры и паузы провайдеров учитываются; отклонённая
раздача не разрешает автоматический выбор. Планы ранее начатых загрузок
не меняются при обновлении темы.
